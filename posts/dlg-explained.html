MY NOTES ON GRADIENT PRIVACY, WRITTEN OUT PROPERLY

Federated learning promises your data never leaves your phone. It doesn't promise the gradient it sends won't give the data away anyway.

I read Zhu, Liu & Han's "Deep Leakage from Gradients" (NeurIPS 2019) — the paper that broke the "gradients are safe to share" assumption behind federated learning — and implemented the attack from scratch in PyTorch, pointing it at my own FedAvg client. This is that, written the way I'd want it explained to me: the reverse-gradient-descent idea, the second-order-derivative trick that makes it possible, and what happened when I actually ran it.

01 · The Question The First Paper Left Open

Okay, but is the gradient actually safe to share?

Federated learning's whole pitch is: raw data never leaves the device, only a trained update does. This paper asks the follow-up nobody wants to hear: is that update actually harmless, or does it secretly still contain the data?

The answer, stated plainly No. Given the gradient, the model's architecture, and its current weights, an attacker can reconstruct the exact private training image — not something similar, the actual image, pixel by pixel — along with its label.

Picture a hospital participating in collaborative learning across several institutions. It never uploads a patient's X-ray. It only sends a gradient computed from that X-ray. The comforting assumption has always been: the server only receives numbers, so it can't know what the X-ray looked like. This paper is the demonstration that the comforting assumption is false.

02 · Why It's Called "Deep" Leakage

Earlier attacks were "shallow." This one goes all the way.

People already knew gradients weren't perfectly silent. What's new here is how much they can be made to say.

Shallow leakage

An embedding layer's gradient is only nonzero for words that actually appeared in training. You learn "the word doctor showed up somewhere" — unordered, ambiguous, not a sentence. Or a GAN generates a synthetic face that looks similar to a training image. Neither one hands you the real data back.

Deep leakage (DLG)

No generative model, no prior knowledge of the dataset, no extra label information required. It's a pure optimization process that recovers the exact original sample — pixel-wise for images, token-wise for text — not a synthetic look-alike.

03 · Turning Gradient Descent Against Itself

The core idea: run training backwards

Normal training goes: data → model → loss → gradient → update the weights. DLG reverses the direction of the question entirely.

Instead of asking "given this data, how should I update the weights?", the attacker asks: "what input data, if I'd used it, would have produced this exact gradient I intercepted?"

Numeric intuition The attacker starts with a completely random dummy image and a random dummy label, feeds them through the (publicly known) model, and computes a dummy gradient G′. They compare it to the real gradient G they intercepted:
\[ D = \|G' - G\|^2 \]
Then — the actual twist — instead of adjusting the model's weights to shrink this distance, they adjust the dummy image and dummy label. Do this enough times, and the dummy image stops looking like static and starts looking like the victim's real photo.
\[ x'^{*}, y'^{*} = \arg\min_{x',y'} \left\| \frac{\partial \ell(F(x',W),y')}{\partial W} - \nabla W \right\|^2 \]

The technical detail that made it click

Matching gradients this way requires differentiating D with respect to the dummy input — but D was itself built from a backward pass. That means computing the gradient of a gradient: a second-order derivative. In PyTorch, this means the first backward pass needs create_graph=True, so the computation graph stays alive long enough for a second backward pass to differentiate through it.

04 · The Loop, Step By Step

The DLG algorithm

  1. Randomly initialize a dummy input x′ and dummy label y′.
  2. Feed them through the model to get a dummy gradient ∇W′.
  3. Compute the distance D = ‖∇W′ − ∇W‖² between the dummy gradient and the real, intercepted one.
  4. Take the gradient of D with respect to x′ and y′ — the second-order step — and update the dummy image and label to shrink D.
  5. Repeat. As D falls, the dummy data converges toward the real training sample.
05 · Where The Attack Gets Harder

Batches of more than one image

Everything above assumes a single image and label per gradient. Real training uses batches, and that complicates things.

With a batch of N images, there are N! possible orderings, and naively updating the whole batch at once makes the optimizer thrash between them without converging. The paper's fix: update one sample in the batch at a time instead of all of them simultaneously.

06 · It's Not Just Images

Attacking a masked language model

Pixels are continuous numbers, so you can nudge a dummy pixel value up or down. Words are discrete — you can't "nudge" the word machine a little bit toward the word learning. The paper's workaround is to attack in embedding space instead.

  1. Take the model's word embeddings instead of raw words.
  2. Initialize random dummy embeddings and run the same gradient-matching loop.
  3. Once the dummy embeddings converge, find the closest real word for each one by nearest-neighbor lookup in the embedding matrix.
How good is the recovery? Starting from meaningless token soup, by iteration 30 the paper recovers full, grammatically coherent sentences almost identical to the original conference announcement text — with only a few mismatches caused by tokenization ambiguity. The authors describe the main content as fully leaked.
07 · Can You Actually Stop This?

Defenses — and why none of them are free

The paper tests several defenses, and the honest finding is: every one of them trades away either accuracy or practicality to buy privacy back.

DefenseDoes it work?Cost
Gaussian / Laplacian noise on gradientsOnly above ~10⁻² varianceMeaningfully hurts accuracy at that scale
Half precision (FP16 / bfloat16)No — fails to protect at allNone, but also no protection
INT8 quantizationYesAccuracy dropped to ~53.7% on CIFAR-100 in the paper's test
Gradient pruning, >20% sparsityYes — the paper's recommended defenseSmallest accuracy cost of the group; compatible with existing compression pipelines
Larger batch sizeMakes the N! ordering problem much harderNot always practical to change
Secure aggregation / homomorphic encryptionStrongest defensePractical limits — integer-only gradients, or server-only compatibility
The nuance worth keeping DLG does not mean "federated learning always leaks everything." It means gradient sharing is not automatically safe, and how vulnerable a system actually is depends heavily on batch size, architecture, and whatever processing is applied to the gradient before it's shared.

09 · Tying It Back To FedAvg

The one sentence I'd give a professor

FedAvg says: don't send the data, send the learning. DLG shows that sometimes the learning itself can reveal the data.

  • DLG reconstructs private training data from a shared gradient — no generative model, no dataset prior, just optimization.
  • It works by reversing gradient descent: optimize the input instead of the weights.
  • It needs second-order derivatives, since it differentiates through a backward pass.
  • Larger batches, gradient pruning, and cryptographic aggregation all make the attack harder — but every defense costs either accuracy or practicality.
  • The scientifically careful takeaway: gradients can leak sensitive training data under certain configurations — not "federated learning always leaks everyone's data."
